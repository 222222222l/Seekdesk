# 使用指南

## 第一次巡查

在「我的简历」上传一份不超过 6 MB 的简历。PDF 最多读取前 80 页，扫描件先做 OCR 或另存为文字版。在同一页设置地点和职位关键词，多个关键词可用空格或逗号分隔。保存后点击「工作概览 → 立即巡查」。

「岗位机会」按当前简历的匹配分降序排列。高匹配为 80–100 分，中匹配为 50–79 分，低匹配为 0–49 分。点开岗位可以查看匹配判断和简历依据。初评分依据已有描述生成，只有标题或摘要的岗位会标为待核实。地点或关键词偏好外的岗位仍可查看。自动联系还要求岗位符合偏好、具备匹配证据，并达到你设置的分数门槛。

首页「匹配机会」只显示通过上述门槛的在招岗位。可在「我的简历」用顿号分隔多个方向或城市，例如职位关键词填「AIGC、agent」，地点填「上海、杭州」。搜索会轮换方向，并在可识别时结合简历的目标职能；工作地点符合任一所选城市即可。搜索索引、职位卡片和地点未核实的线索可在「全部岗位」查看。

### 用自然语言生成筛选条件

在「模型与任务」选用已接入的模型 API 或 Agent CLI。进入「我的简历 → 自然语言筛选助手」，输入求职需求，点击「生成并应用条件」。例如：“找上海或杭州的产品经理，岗位涉及 AIGC 或智能体，排除工业设计岗，公告月薪下限至少 2 万元，游戏业务优先。”

页面会列出模型生成的职能、必备词、排除词、城市和搜索短语。点击「查看符合条件的岗位」可查看当前库存中的结果。地点和公告月薪有硬性要求时，缺少证据的岗位会被筛出；优先词用于同分排序。生成条件只在本地重新筛选岗位，后续巡查继续使用这些条件和搜索词。首页推荐和自动联系仍需通过简历匹配门槛。

可接着输入“地点改为杭州”修改现有条件。遇到无法执行的要求，页面会列出待澄清项，继续沿用上次生效的条件。点击「停用并恢复手动偏好」即可切回原有设置。

## 添加来源

在「来源与账号」勾选国内、海外或两者，然后保存。选择适用于巡查、岗位清单和首页匹配机会。来源指发布岗位的网站，例如 Greenhouse 上的上海岗位归入海外平台。企业官网可以手动归类。未归类且无法识别地区的网站只在同时选择两个地区时纳入。

| 来源 | 设置方法 |
| --- | --- |
| Greenhouse / Lever | 在「公开招聘板」中每行填写一个标识，如 `greenhouse:gitlab`、`lever:spotify`。从企业使用的招聘板网址确认企业标识。 |
| 企业官网 | 填写企业招聘首页或具体岗位页的完整 URL。优先识别 JobPosting 结构化数据，也支持明确列出任职要求的单岗位页。 |
| BOSS 直聘、猎聘、智联招聘 | 可分别选择平台官网直连和公开索引。直连默认关闭。官网要求登录或验证时暂停，人工核对后可点击「我已核对，解除后台直连暂停」。单次可见复查只读取当前窗口。 |
| 前程无忧 | 支持本地 SearXNG 的公开岗位索引和手动导入职位链接。线索显示为待核实。 |
| 腾讯社招、字节跳动社招、网易招聘的官网索引 | 可逐个勾选。通过本地 SearXNG 获取带职位编号的官网详情链接，摘要保存为线索。网易招聘可能同时包含校招和社招。 |
| 腾讯社招 | 在国内来源中单独启用。每轮按当前关键词取一页官网结果，使用职位编号核对职责和要求。只读到清单的岗位保存为卡片，未出现在本轮搜索的旧岗位保留。 |
| 博世中国岗位 | 在「企业官网直连」勾选。通过 SmartRecruiters 公开接口分批检查中国区清单，在本机按搜索词核对标题和地点，每轮最多读取八个匹配详情，其余匹配项保留为卡片。相同搜索词下次从后续页面继续。[官方职位接口](https://developers.smartrecruiters.com/docs/endpoints) |
| Brave Search / Tavily | 填写相应服务的 API 密钥。巡查会用简历生成的职位查询词寻找企业招聘页，并核对结果页的岗位内容。 |

公开招聘板会根据成功读取的完整清单更新下线状态。三家招聘平台开启直连后每轮最多跟进八个职位详情，其余可读卡片仍会保存。公开岗位索引需要启用本地 SearXNG，在平台直连关闭或暂停时也能运行。仅勾选海外来源会跳过国内索引。

在「来源与账号 → 导入已收藏的岗位」粘贴岗位名称、一个空格和官网职位链接，每行一条。支持上述四家招聘平台，按职位标识合并。导入只保存本地线索，不访问链接。索引和导入的记录可在「全部岗位」查看。

在「沟通与通知 → 巡查记录」展开一轮巡查，点击「查看本轮岗位」可按简历匹配分查看新增、内容有变化或重新开放的岗位。遇到官网验证时，记录会同时显示已读取的卡片数和验证提示。旧版记录可按首次发现时间查看当轮新增岗位。

自动发现岗位时使用免登录的公开请求。开启自动联系后，只有完整岗位满足筛选条件、匹配门槛和简历证据要求时，才用该平台已保存的登录资料发起新聊天。此前联系的 HR 会话继续使用原账号接收邀请。手动点击「可见窗口复查」时也会打开该平台的专属浏览器。

在「模型与任务 → 求职提醒」选择 Windows 通知或邮件。关闭自动发简历时，HR 的简历邀请会触发待投递提醒。开启自动发送时，确认发送成功后会提醒。在 Windows 上，未配置可用邮箱时，投递提醒自动使用本机弹窗。如果系统通知也不可用，提醒会保留为待处理，渠道恢复后补发。

### 安装或连接 SearXNG

在「来源与账号 → 本地 SearXNG」选择一种方式。

| 方式 | 适用情形与操作 |
| --- | --- |
| 安装独立实例 | 先启动本机 Docker 引擎并确认可运行 `docker compose version`。选择「安装独立实例（Docker）」并安装。工作台会创建配置、启用 JSON 搜索并分配本机端口。 |
| 导入本地 Compose 项目 | 填写项目目录的绝对路径。项目需包含 Compose 文件、名为 `searxng` 的服务，以及容器 8080 端口的本机映射。工作台会启动该服务。 |
| 连接已运行的实例 | 填写该实例的本机地址，如 `http://127.0.0.1:8888`。适用于已有服务，也适用于使用其他 Compose 服务名或端口的安装。 |

点击「测试搜索」查看 JSON 查询结果，再确认插件显示「已加入巡查」。若实例返回 HTTP 403，在实例的 `settings.yml` 中将 `json` 加入 `search.formats` 并重启实例。如果 JSON 接口正常但上游引擎超时，检查容器到搜索引擎的网络。独立安装支持填写容器可访问的出口代理。移除导入的实例只会移除工作台中的接入记录。[SearXNG 搜索接口说明](https://docs.searxng.org/dev/search_api.html)

## 切换模型

打开「模型与任务」，选择后端，扫描模型目录或手填模型 ID。点「测试连接」验证当前账号能调用所选模型，再点「使用此后端和模型」。切换在下一轮巡查生效。连接测试使用简短测试请求。

- **本地关键词匹配**适合首次使用，无需模型账号。
- **Agent CLI** 支持 Pi、Codex、Claude Code、Gemini CLI 和 OpenCode。先在本机安装并登录，使命令能从启动工作台的环境找到。界面标明安装状态。可枚举的 CLI 会读取目录，Claude Code 提供官方别名。
- **模型 API** 提供 OpenAI、DeepSeek、通义千问、Kimi、智谱、硅基流动、OpenRouter、Anthropic 和 Gemini 预设。本机可接入 Ollama、LM Studio，也可填自定义兼容 API 的基址和模型 ID。兼容接口的基址通常包含版本路径，例如 `http://127.0.0.1:8000/v1`。

外部模型每轮每个来源最多新评估八个岗位，其余先用本地初评分排序。更换简历后，已保存的岗位会按新简历重新进行本地匹配。模型目录中的选项受服务商、CLI 版本和账号权限影响。

## 定时巡查与投递

在「模型与任务」保存巡查间隔、匹配门槛和每日新联系上限。默认间隔为 60 分钟，门槛为 80 分，每日最多新联系 5 人。勾选「启用定时巡查」后，保持本机服务运行。电脑休眠或服务退出期间任务暂停，服务恢复后会检查已到期的任务。

自动打招呼和受邀发送简历有独立开关。打招呼会引用简历中的经历。受邀发送针对工作台已联系的会话，使用首次联系该岗位时关联的简历附件。在「沟通与通知 → 巡查记录」可看到来源读取数、评估数和失败原因。遇到「待核对」时，先查看平台会话，确认未送达后再使用「已核实未发，重新排队」。

## 求职提醒

- **只在本机提醒**。在「模型与任务 → 求职提醒」勾选「Windows 桌面通知」，可取消「邮件提醒」，然后保存。点击「试弹一条通知」检查系统是否接受。工作台服务需要在已登录的 Windows 桌面会话中运行。
- **给自己发邮件**。启用「邮件提醒」并选择快捷设置。QQ、163、126 邮箱只需填写邮箱地址和该邮箱生成的客户端授权码。先在邮箱官网开启 SMTP 服务。
- **独立发件账号**。选择「自定义 SMTP」，填写收件地址、发件账号、授权凭据以及服务商指定的主机和端口。465 端口使用隐式 TLS，其他端口使用 STARTTLS。

收到交换联系方式请求、或发现匹配的企业官网岗位并生成备料建议时，工作台会按所选渠道提醒。两种渠道可以同时启用，处理详情保存在「沟通与通知」。

## 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 如何完成可见窗口复查 | 复查打开一次搜索页，读取已加载的卡片和页面内的结构化职位信息。若需要更多详情，可以手动打开感兴趣的岗位。读到卡片后窗口最多保留三分钟，关闭窗口或点「完成窗口核对」即可保存。三个平台遇到访问验证都会停止，并保留已读岗位。 |
| 猎聘复查打开空白标签 | 如果「来源与账号」提示后端仍是旧版，在原工作台服务终端按 Ctrl+C，再双击「启动工作台.cmd」。如果官网要求验证，可在「打开平台登录」窗口人工处理。 |
| 复查报告官网页面反复跳转 | 本轮停止并保留已读卡片。人工核对后若要恢复已启用的直连，可单独解除暂停。关闭窗口或成功读到详情会保留原有的暂停状态。 |
| 岗位只有摘要或本轮没有新岗位 | 查看巡查记录里每个来源的说明。检查搜索词、企业招聘板标识和岗位是否仍开放，点开原始链接核实。 |
| 读不到简历内容 | 使用可复制文字的 PDF、DOCX、TXT 或 Markdown；扫描件先做 OCR。文本提取上限为 12 万字。 |
| CLI 有模型目录，但测试连接失败 | 在启动工作台的同一用户账户下检查 CLI 登录、模型 ID 和服务权限。自定义 API 也需要核对基址与版本路径。 |
| 关闭网页后没有收到弹窗 | 确认服务仍运行，点击「试弹一条通知」，检查 Windows 的通知设置、勿扰模式与通知中心。 |
| 端口已占用或找不到之前的数据 | 使用启动终端显示的实际地址。手动启动可指定 `--port 8766`，或通过 `--data-dir` 选择原数据目录。同一目录同时只运行一个服务实例。 |

## 备份与更新

退出服务、关闭各平台登录窗口，再复制整个 `.workbench/personal/` 到可信位置。该目录包含简历、SQLite 数据库、登录会话与设置。Windows 密钥由当前用户的 DPAPI 保护，换机或更换系统账户后可能需要重新填写。

Git 安装可在停止服务后执行 `git pull --ff-only`，然后使用安装时的启动方式重新运行。手动安装可再次执行 `python -m pip install -r requirements.txt` 和 `python -m playwright install chromium`，其中 `python` 应指向项目虚拟环境。

侧栏底部的「人工审阅台」可载入虚构履历和公开样本，单独记录手动核查结果。它将记录保存在当前浏览器的 localStorage；备份主工作台数据目录时，人工审阅台的记录需在原浏览器中另行导出。
